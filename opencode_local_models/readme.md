# *Up and Running* with OpenCode and Local Ollama Models

## Introduction

This tip shows how to run a local AI model on your MacBook while using [OpenCode](https://opencode.ai) on MSI Agate. This is useful when your code and data live on MSI, but you want model responses to be generated by a free, open-weight model running locally on your Mac. In this case, your data and prompts are not sent to LLM providers (e.g. Google, Anthropic, OpenAI, etc.).

The basic idea is:

- Your MacBook runs [Ollama](https://ollama.com) and the local model.
- MSI Agate runs OpenCode.
- An SSH reverse tunnel lets OpenCode on Agate talk to Ollama on your Mac.

```
MacBook                 Staff login              Agate login              SLURM compute
=======                 ===========              ===========              =============

Ollama service
localhost:11434
    |
    | local model
    | qwen3 / qwen3-coder / gemma
    |
    +====================+
      reverse tunnel     |
                         |
                    localhost:11434
                         |
                         +========================+
                           reverse tunnel         |
                                                  |
                                             localhost:11434
                                                  |
                                                  +========================+
                                                    local tunnel           |
                                                                            |
                                                                       localhost:11434
                                                                       OpenCode TUI: oc

You type prompts on Agate or a SLURM compute node.
The model runs on your Mac using your Mac's GPU.
Answers return to OpenCode on MSI.
```

To run OpenCode with local Mac models from Agate, we need to:

- Install Ollama on the Mac
- Download one or more local models
- Start an SSH reverse tunnel from the Mac to Agate
- Optionally jump from the Agate login node to a SLURM compute node
- Load OpenCode on Agate
- Configure OpenCode to use the tunneled Ollama endpoint
- Run OpenCode and test a prompt


## Install Ollama on Your Mac

I recommend installing Ollama with Homebrew because it is easy to update, remove, and include in a reproducible Mac setup.


If you don't have Homebrew installed, open a terminal on your MacBook and run:

```
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
```

Otherwise, open a terminal on your MacBook:

```
brew install ollama
brew services start ollama
```

Verify that Ollama is running:

```
brew services list
curl http://localhost:11434/api/version
ollama list
```

If `ollama list` works, Ollama is running. It is OK if the model list is empty before you download your first model.


## Download a Model

For bioinformatics coding work, including R, Python, Bash, Nextflow, SLURM scripts, and general Linux troubleshooting, start with one good default model rather than downloading many models at once.

Recommended first model for most M1, M2, and M4 MacBooks with at least 24-32 GB RAM:

```
ollama pull qwen3:14b
```

Recommended coding model if your Mac has enough memory, especially 32 GB or more:

```
ollama pull qwen3-coder:30b-a3b-q4_K_M
```

Optional faster model for quick questions:

```
ollama pull gemma3:12b
```

Check installed models:

```
ollama list
```

You do not need to run `ollama run` before using OpenCode. OpenCode will ask Ollama to load the model when you send the first prompt.


## Model Recommendations

These are practical starting points for Apple Silicon MacBooks used for bioinformatics coding.

| MacBook memory | Recommended default | Coding model | Fast model | Notes |
| --- | --- | --- | --- | --- |
| 16 GB | `qwen3:8b` | `qwen2.5-coder:7b` | `gemma3:4b` | Use smaller models for responsiveness. |
| 24 GB | `qwen3:14b` | `qwen2.5-coder:14b` | `gemma3:12b` | Good for most coding questions. |
| 32 GB | `qwen3:14b` | `qwen3-coder:30b-a3b-q4_K_M` | `gemma3:12b` | Good balance for M1/M2/M4 Pro systems. |
| 48-64 GB | `qwen3:32b` | `qwen3-coder:30b-a3b-q4_K_M` | `gemma3:12b` | Larger context and better reasoning are more practical. |

For most people, I would start with:

```
ollama pull qwen3:14b
```

Then add the coder model only if you want better coding-agent behavior and have enough memory:

```
ollama pull qwen3-coder:30b-a3b-q4_K_M
```

The coder model is larger, but it is useful for debugging, refactoring, Bash scripts, Nextflow workflows, and repository-aware OpenCode sessions.


## Start the Reverse SSH Tunnel

Run this command from your Mac terminal, replacing `USERNAME` with your MSI username:

```
ssh -R 11434:localhost:11434 USERNAME@agate.msi.umn.edu
```

This means:

- Your Mac is listening on `localhost:11434` with Ollama.
- Agate will also have a `localhost:11434`.
- Requests sent to `localhost:11434` on that Agate login node are forwarded back to Ollama on your Mac.

After logging in, check which Agate login node you are on:

```
hostname
```

The easiest option is to run OpenCode in this same SSH session. If you open a second Agate shell, make sure it lands on the same login node. The reverse tunnel only exists on the Agate node where the SSH connection was opened.

Test the tunnel from Agate:

```
curl http://localhost:11434/api/version
```

If that returns an Ollama version, Agate can reach Ollama on your Mac.


## Use a Specific Agate Login Node and SLURM Compute Node

My current setup first connects to the MSI staff host, then jumps to a specific Agate login node, then requests an interactive SLURM compute node. This is useful because the reverse tunnel only exists on the machine where the SSH connection lands.

From your Mac, open the first SSH connection to `staff.msi.umn.edu` and create the first reverse tunnel:

```
ssh -R 11434:localhost:11434 USER@staff.msi.umn.edu
```

From the staff shell, jump to the specific Agate login node and create the second reverse tunnel:

```
ssh -R 11434:localhost:11434 ahl02.agate.msi.umn.edu
```

Now you should be on `ahl02`. Confirm that the tunnel works on the Agate login node:

```
hostname
curl http://localhost:11434/api/version
```

Then request an interactive SLURM compute node:

```
srun --pty --x11 --mail-type=NONE --nodes=1 --ntasks-per-node=1 --tmp=40gb --partition=msismall --mem=32gb --cpus-per-task=1 --time=8:00:00 bash -l
```

After `srun` starts, you are no longer on `ahl02`; you are on a compute node. Because `localhost` now means the compute node, create one more local tunnel from the compute node back to `ahl02`:

```
ssh -fN -L 11434:localhost:11434 ahl02.agate.msi.umn.edu
```

Then test from the compute node:

```
hostname
curl http://localhost:11434/api/version
```

If that returns an Ollama version, OpenCode running on the compute node can reach Ollama running on your Mac. The full path is:

```
compute localhost:11434
    -> ahl02 localhost:11434
    -> staff localhost:11434
    -> Mac localhost:11434
    -> Ollama
```

If the compute-node `ssh -fN -L ...` command says the port is already in use, another tunnel may already be running in that compute session. Try the `curl` test before starting another one.


## Load OpenCode on Agate or the Compute Node

On Agate, or after your interactive SLURM session starts, load my OpenCode module:

```
module load /projects/standard/lmnp/knut0297/software/modulesfiles/opencode/1.18.4
```

After loading the module, both `opencode` and `oc` should be available. I recommend `oc` because it is a wrapper that behaves better on the MSI filesystem and saves session backups if OpenCode crashes or a job ends.


## Configure OpenCode

Create or edit this file on Agate:

```
~/.config/opencode/opencode.json
```

Example configuration for the three models listed above. If you only downloaded `qwen3:14b`, remove the `qwen3-coder` and `gemma3` entries from both `whitelist` and `models`.

```json
{
  "$schema": "https://opencode.ai/config.json",
  "autoupdate": false,
  "permission": {
    "read": "allow",
    "glob": "allow",
    "grep": "allow",
    "list": "allow",
    "external_directory": "allow"
  },
  "provider": {
    "ollama": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Ollama (local Mac)",
      "options": {
        "baseURL": "http://localhost:11434/v1"
      },
      "whitelist": [
        "qwen3:14b",
        "qwen3-coder:30b-a3b-q4_K_M",
        "gemma3:12b"
      ],
      "models": {
        "qwen3:14b": {
          "name": "Qwen 3 14B"
        },
        "qwen3-coder:30b-a3b-q4_K_M": {
          "name": "Qwen 3 Coder 30B A3B Q4_K_M"
        },
        "gemma3:12b": {
          "name": "Gemma 3 12B"
        }
      }
    }
  }
}
```

The important settings are:

- `"baseURL": "http://localhost:11434/v1"` points OpenCode to the Ollama OpenAI-compatible API.
- The `models` keys must exactly match the model names shown by `ollama list` on your Mac.
- The `whitelist` keeps the OpenCode model list focused on the local models you actually installed.


## Run OpenCode

From a project directory on Agate or on the compute node:

```
oc
```

Inside OpenCode, type:

```
/models
```

Choose one of your local Ollama models, or keep the default `qwen3:14b`.

Try a simple prompt:

```
what is my current working dir?
```

The first response may take longer because Ollama has to load the model into Mac memory. After that, responses should start faster.

In a second Mac terminal, you can watch what Ollama is doing:

```
ollama ps
```


## Troubleshooting

### OpenCode says it cannot connect to Ollama

On Agate, run:

```
curl http://localhost:11434/api/version
```

If this fails, the SSH tunnel is not working or you are on the wrong Agate login node.


### I opened a second Agate shell and it does not work

The reverse tunnel is attached to the Agate login node from your original SSH command. Run `hostname` in both shells. They need to match, or you should run `oc` in the original tunneled shell.


### OpenCode shows a model, but the request fails

On your Mac, confirm the model is installed:

```
ollama list
```

The model name in `opencode.json` must exactly match the name from `ollama list`.


### The model is too slow or uses too much memory

Use a smaller model. For example:

```
ollama pull qwen3:8b
```

Then add `qwen3:8b` to the OpenCode `models` list and use it as your default.


### The model is answering, but coding quality is not good enough

Try the coder model if your Mac has enough memory:

```
ollama pull qwen3-coder:30b-a3b-q4_K_M
```

Then switch models inside OpenCode with:

```
/models
```
